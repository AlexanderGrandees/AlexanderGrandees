## Пользовательское поведение
«Векси, давай придумаем два варианта вечера» начинает разговор. «Второй подробнее», «нет, дома», «а подешевле?» продолжают ту же задачу без имени, пока реплика распознана как продолжение.
«Хмм», «мм», «ии» — тишина, без записи в память и вызова модели.
«Стоп» отменяет текущий ответ и приостанавливает слушание, сохраняя задачу. «Продолжим» после нового обращения возобновляет её.
«Забудь этот разговор» очищает оперативный контекст. «Задача завершена» завершает задачу явно.
«Новая тема» создаёт отдельный контекст; незавершённая старая задача получает SUSPENDED, не COMPLETED.
По умолчанию имя пользователя почти не звучит. Настройка «Обычно» разрешает редкие естественные обращения; имя не извлекается из памяти владельца для гостя.

## Две независимые машины состояний
Conversation: IDLE → LISTENING → THINKING → SPEAKING → LISTENING. Таймаут очереди реплик или «стоп»: PAUSED. Явное закрытие: CLOSED.
Task: ACTIVE ↔ AWAITING_INPUT / BLOCKED / SUSPENDED; только явное завершение/отмена переводит в COMPLETED / CANCELLED.
Таймаут прослушивания не удаляет цель, факты или задачу. После паузы требуется новое обращение либо надёжное подтверждение адресованности.
Прототип DialogueContext реализует IDLE/LISTENING/THINKING/PAUSED/CLOSED; SPEAKING остаётся в существующем ConversationSession. Адаптер связывает их событиями, не объединяет task и turn timeout.

## Контракты
- IngressDecision: attention_class, accept/drop, reason_code, actor_ref, session_id, contextual_evidence, privacy_ref. Текста в audit нет.
- DialogueContext: session_id, revision, explicit_objective, accepted_turn_pairs, state. Только RAM; приватный repr.
- GenerationTicket: session_id + revision. Ответ применим только к текущему запросу той же сессии. Перебивание, изменение цели, пауза и закрытие инвалидируют билет.
- ContextFact (следующий слой): value, source_kind, source_turn_id, revision, verification_time, status ACTIVE/STALE/CONFLICT. Утверждение модели не считается проверенным фактом.
- ExpectedResponse: question_id, kind NONE/CHOICE/CLARIFICATION, valid_choices, originating_revision. «Да» имеет смысл только для актуального вопроса; не выдаёт разрешения на действия.
- ModelReply: text, model_id, generation_ticket, finish_reason. Никаких исполняемых tool_calls.
- ActionResult: существующий Result + Evidence. Только проверенное действие может породить сообщение об успехе.

## Источники и изменения
Для состояния ПК: свежий результат адаптера выше старого снимка; слова пользователя — запрос/сообщение, а не доказательство выполнения.
Для пожеланий: последняя явная поправка пользователя выше прежней формулировки и догадки модели.
Изменение цели увеличивает revision; поздний ответ по старой цели отбрасывается. Смена окна/документа инвалидирует соответствующие target refs. Модель не может снять STALE или CONFLICT.
Память недавних реплик ограничена 12 парами и 12000 символами. Явная цель хранится отдельно, не исчезает при вытеснении старых реплик. Символьный лимит не заменяет токеновый лимит адаптера.
Сжатые моделью резюме — неподтверждённые производные данные; не перезаписывают цель и подтверждённые факты. Если нужная деталь уже вытеснена, требуется уточнение.

## Attention и музыка/игра
Нельзя считать любую речь в течение 90 секунд продолжением. Семантической близости тоже недостаточно: реплика из STALKER может подходить к теме.
Порядок: локальный VAD/эхо/качество → фильтр междометий → обращение или evidence продолжения → privacy gate → контекст/LLM.
До принятия реплики запрещены её запись, добавление в историю и отправка в генеративную модель. AMBIENT/UNKNOWN → DROP с освобождением ссылок на буферы; forensic zeroization не обещается.
Продолжение допускается при ожидаемом ответе с соответствующей формой либо подтверждении адресованности доступным входным адаптером. Одна временная близость не является идентификацией говорящего.
Открытый разговор и шумный режим должны быть отдельными настройками. Для игры — более строгая адресованность, возможность push-to-talk; нельзя объявлять распознавание источника решённым без полевого теста.
Пока такого адаптера нет, свободный диалог сначала проверяется через явно направленный текстовый/кнопочный вход. Голосовой whitelist нельзя просто заменить на accept=True.

## Приватность и полномочия
Новая capability LOCAL_CONVERSATION отвечает только за добровольно переданный текст текущей беседы; не даёт доступа к OWNER_MEMORY, файлам, истории других сессий или бизнес-данным.
В текущей policy LOCAL_MODEL разрешён только для PUBLIC. Эта политика не изменена прототипом. Свободную речь нельзя автоматически классифицировать PUBLIC.
Для расширения требуется отдельный проверяемый route contract: cumulative DataClass, actor/scope, purpose local_conversation, lawful_basis applicable/not-applicable с основанием, destinations loopback_only, retention session_RAM, deletion explicit_forget/close/process_exit, redaction/encryption и approval class. UNKNOWN high-risk остаётся BLOCKED.
SECRET не направляется в модель. Один regex не гарантирует определение всех секретов. Для RESTRICTED_CASE/SPECIAL_CATEGORY требуется отдельный разрешённый маршрут; обычный чат его не открывает.
Гостевой контекст не смешивается с контекстом владельца. Переключение подтверждённого speaker/session закрывает текущую генерацию. Без speaker binding история не считается приватной owner memory.
Без записи raw transcript в логи/Notion/GitHub. Поддержать явное забывание; системный swap/crash dump и логи сервера Ollama требуют отдельной проверки — RAM-only приложения не доказывает отсутствие копий в ОС.

## Модельный адаптер
LocalConversationClient: только фиксированный loopback endpoint; запрет удалённого адреса, redirects, proxy environment и внешнего fallback. Модель берётся из установленного списка, загрузка новой модели не происходит скрытно.
Интерфейс generate(messages, ticket, cancel_event) возвращает ModelReply либо typed TIMEOUT/UNAVAILABLE/INVALID_RESPONSE/CANCELLED.
Бюджеты: вход ограничен до обращения к серверу; num_ctx 6144, num_predict 256 как стартовые настройки для измерений. Ограничение размера ответа, wall-clock deadline и отмена обязательны; requests timeout сам по себе не является общим дедлайном.
System prompt: русский, короткий естественный ответ; соблюдение выбранной частоты имени; нет доступа к ПК/файлам/памяти; нельзя заявлять о выполнении действий. Prompt не является security boundary.
Команды маршрутизируются в typed executor отдельно. Ошибка/запрет команды не заменяется ответом модели «сделано». Ответ модели никогда повторно не проходит через command router.
После ошибки текущая неуспешная пара не входит в историю; предыдущая задача остаётся доступна.

## Regression matrix
Проверены в прототипе: цель и история после паузы; отклонение позднего ответа; отмена при паузе; невозможность использовать билет другой сессии; очистка при закрытии; ограничение истории без потери цели; поправка инвалидирует ответ; repr/errors без payload; пустой ответ не сохраняется.
Обязательные оставшиеся cases: три связанных вопроса; «второй/нет/подробнее»; фон до/во время/после TTS; музыка+STALKER; SECRET/unknown classification; guest→owner switch; ложное «сделано»; remote endpoint/redirect/proxy; timeout/cancel; переполнение; restart forgetting; late reply after forget; stale app target.
Статусы model eval, microphone field, install/launch для нового диалога: NOT_RUN. Успех тестов памяти не является доказательством работоспособности полного диалога.

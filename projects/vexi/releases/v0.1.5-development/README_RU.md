# Vexi 0.1.5.dev1 — A+B+C development package

Это отдельный инженерный стенд. Не запускайте старый публичный установщик и не копируйте эту папку поверх рабочей v0.1.4 на ноутбуке. Сборка ещё не сохраняет весь набор команд предыдущей версии.

Реализованы foundation-контракты, новый входной голосовой контур, guest-safe media, scoped owner draft creation, политика разрешений и базовые stale/source primitives. Полная спецификация: `ENGINEERING_ABC.md`.

Проверено на Windows / Python 3.11.9:

- Синтаксис 43 Python-файлов.
- 42 поведенческих теста A+B+C.
- Исходный regression script v0.1.4; его проверки Router частично являются поиском строк в исходниках.
- Отдельный текстовый процесс: READY; owner создал синтетический файл, guest не смог создать файл.
- Замена целого набора модулей в изолированной папке и восстановление baseline по контрольным суммам.

NOT RUN: голосовой field test, реальный Browser Pack и тест на ноутбуке. Media-тесты используют fake pack. Не путайте их с подтверждённым YouTube E2E.

## Запуск текстового стенда

Распакуйте ZIP в отдельную папку. Нужен Python 3.11+.

```powershell
python core/foundation_console.py --workspace ./test-documents
```

Гостевой режим по умолчанию. Проверочные реплики: `привет`, `какая версия`, `создай черновик denied.txt: synthetic`, `exit`.

Для доверенного локального owner-сеанса, запущенного владельцем из собственной OS-сессии:

```powershell
python core/foundation_console.py --owner-console --workspace ./test-documents
```

Реплика: `создай черновик proof.txt: synthetic`. Затем `задача завершена`, `exit`. Это локальная операторская поверхность; она не выдаёт OWNER голосовому входу и не заменяет будущую повторную аутентификацию на общем ПК.

## Автоматические проверки

```powershell
python -m unittest discover -s foundation/tests -v
```

## Голосовой кандидат

После установки голосовых зависимостей в отдельное окружение и настройки локальных моделей:

```powershell
python core/vexi.py
```

Автозапуск не создаётся. Микрофон работает как UNKNOWN. Перед каждой новой голосовой репликой пока требуется wake-имя; надёжная привязка продолжений к говорящему ещё не подключена. Свободный разговор с LLM также пока не подключён к новому privacy-контракту. Контекст задачи при этом не удаляется по таймеру.

Гостевые команды текущего стенда: `пауза`, `продолжи видео`, `весь экран`, `сверни это видео`, `сделай видео тише/громче`. Требуется Chrome Browser Pack с открытым YouTube video. Generic browser/app control и личная память не пробрасываются в старый Router.

## Полевой журнал на ноутбуке

Записывать OBSERVED / FAIL / NOT RUN; PASS только с наблюдением и датой.

1. Запуск в отдельной папке: видимая версия 0.1.5.dev1 и отсутствие второй конфликтующей Vexi.
2. Разговор людей без обращения: ни ответа, ни отображения/записи распознанного текста.
3. Wake + media action: свежая вкладка и фактическое состояние плеера после команды.
4. Barge-in во время TTS: остановка звука без автоматического ответа на фон.
5. Другой человек просит файлы/память/почту: нет доступа и раскрытия.
6. Подмена вкладки во время команды: зафиксировать ограничения Browser Protocol v1; до атомарной привязки не повышать статус релиза.
7. При сбое закрыть отдельный процесс/окружение; рабочая v0.1.4 остаётся исходной. Для production-замены нужен отдельный проверенный installer и backup рабочего Core.

DOCX/PDF/Live Office, полный document lifecycle, свободный разговор и безопасное продолжение без wake-имени — последующие незавершённые части. Это не Stable и не Public Preview replacement.
